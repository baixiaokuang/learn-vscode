## 8. Artificial Intelligence and Copilot Architecture

The integration of AI (GitHub Copilot) necessitated new architectural primitives beyond standard LSP.

### 8.1 Ghost Text Implementation

Standard autocomplete uses a widget (dropdown). AI suggestions (multi-line code predictions) use **Ghost Text**—gray text that appears inline.27

- **Decorations vs. View Zones:**

  - **Single-line suggestions:** Implemented using standard CSS `::after` text decorations on the cursor line.

  - **Multi-line suggestions:** Requires shifting the existing text down. This is done using **View Zones**—a mechanism in the Monaco Editor that allows inserting arbitrary vertical space between lines. The Ghost Text is rendered into this reserved space.28

- **The "Shadow" Buffer:** Internally, the editor maintains a shadow state of what the text _would_ look like if the suggestion were accepted, ensuring that syntax highlighting can run on the ghost text (giving it proper colors instead of just gray) before it is even committed.

### 8.2 The Language Model API

VS Code is standardizing AI access via the **Language Model API**.30

- **Abstraction:** Extensions no longer need to bundle the OpenAI SDK or manage API keys. They request a `LanguageModel` from the host.

- **Selectors:** Extensions can query for models based on capabilities: `vscode.lm.selectChatModels({ family: 'gpt-4' })`.

- **Streaming:** The API is fundamentally stream-based (`AsyncIterable`), allowing the UI to type out the AI's response in real-time.

### 8.3 Prompt Engineering with `prompt-tsx`

To manage the limited context window of LLMs (e.g., 8k or 32k tokens), VS Code introduced the `@vscode/prompt-tsx` library.31

- **Component Model:** Prompts are built using a React-like component hierarchy.

- **Flexibility:** Components have properties like `flexGrow` and `priority`.

  - _Scenario:_ You have the user's question, the current file, and the chat history. The context limit is reached.

  - _Logic:_ The library preserves the user question (High Priority). It includes the current file. It then iteratively prunes the chat history (Lower Priority) until the prompt fits the token budget.

  - _Significance:_ This moves prompt engineering from string concatenation spaghetti code to a structured, declarative UI-like discipline.

### 8.4 Inline Completion Pipeline (Code Map)

- **Data model:** `GhostText` / `GhostTextReplacement` in `src/vs/editor/contrib/inlineCompletions/browser/model/ghostText.ts` hold the parts that will be painted; `computeGhostText(...)` diffing (`computeGhostText.ts`) trims shared prefixes/indentation and splits preview italics vs. solid text.
- **Controller/model:** `InlineCompletionsModel` converts inline suggestion edits into `GhostText` instances and exposes `primaryGhostText` for UI + partial-accept flows; `InlineCompletionsController` binds context keys (e.g. `cursorBeforeGhostText`) and accessibility updates from the active ghost text.
- **Rendering:** `GhostTextView` (`.../view/ghostText/ghostTextView.ts`) injects single-line text via `InjectedText` decorations and uses `AdditionalLinesWidget` view zones for multi-line predictions; it applies a shadow `StringEdit` + `textModel.tokenization.tokenizeLinesAt(...)` so ghost text is syntax-highlighted even though it is not in the buffer.
- **UX plumbing:** Hover/warning widgets and accessibility output read from `primaryGhostText` (see `inlineCompletionsAccessibleView.ts`, `hoverParticipant.ts`) and reuse the same `GhostTextAttachedData` to detect clicks/hover on injected text.

### 8.5 Language Model API Wiring (Host <-> Extension)

- **Service of record:** `LanguageModelsService` (`src/vs/workbench/contrib/chat/common/languageModels.ts`) owns the `languageModelChatProviders` extension point, caches metadata (`vendor/id/family`, capabilities), persists user visibility overrides, and routes `sendChatRequest`/`computeTokenLength` to the right vendor provider.
- **Main thread bridge:** `MainThreadLanguageModels` registers vendor providers coming from the extension host, wraps responses in `AsyncIterableSource` streams, resizes vision image parts before forwarding, and exposes provider-change events; it also injects a per-provider `LanguageModelAccessAuthProvider` so cross-extension LM use can be gated.
- **Extension host side:** `ExtHostLanguageModels` adapts the `vscode.lm` API—caches `LanguageModelChatInformation`, converts `LanguageModelChatMessage2` to internal `IChatMessage`, batches `Progress` parts before `$reportResponsePart`, and enforces proposed-api checks for system messages/tool-calling.
- **Model pickers in UI:** Chat input (`src/vs/workbench/contrib/chat/browser/chatInputPart.ts`) observes `ILanguageModelsService` to populate the picker, persist the chosen model, and fall back to defaults if a model disappears or becomes non-user-selectable.

### 8.6 Tool Calling and `prompt-tsx` Results

- **Tool registry/execution:** `ILanguageModelToolsService` (`src/vs/workbench/contrib/chat/common/languageModelToolsService.ts`) tracks tool metadata (source, tags, schemas) and runs invocations with progress + token-count callbacks; results can include text, data buffers, or structured prompt-tsx parts.
- **Bridges:** `MainThreadLanguageModelTools` proxies tool registration/invocation to `ILanguageModelToolsService`; `ExtHostLanguageModelTools` registers extension-provided tools and forwards progress/token counting back to the host.
- **prompt-tsx serialization:** `stringifyPromptTsxPart` and `PromptElementJSON` types stringify prompt-tsx tool results so they can be rendered/streamed like other LM parts (see `promptTsxTypes.ts`).
- **Surface usage:** Chat and inline chat attachments, plus terminal chat tools, consume `ILanguageModelToolsService` so tool calls can show confirmation, progress, and rich input/output while an LM response streams.

### 8.7 Ghost Text Outside the Editor

- **Terminal safety:** Terminal prompt detection (`src/vs/platform/terminal/common/capabilities/commandDetection/promptInputModel.ts`) scans xterm buffer cells for ghost-text styling to avoid treating Copilot suggestions as real input.
- **Voice workflows:** Speech-to-text overlays in the terminal (`src/vs/workbench/contrib/terminalContrib/voice/browser/terminalVoice.ts`) render and clear ghost text during voice entry using the same injected-text/view-zone primitives.
